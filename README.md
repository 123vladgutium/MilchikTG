# MilchikTG — обновление интерфейса и мобильной версии

Это обновление для уже существующего MilchikTG. Оно не удаляет аккаунты, чаты или сообщения.

## Что нового
- Полностью обновлён тёмный интерфейс: более чёткая навигация, мягкие поверхности, улучшенные карточки и кнопки.
- Исправлен выход из переписки на телефоне: чат скрывается, экран возвращается к списку, подписка конкретного чата отключается.
- Настройки на телефоне открываются удобной нижней панелью, вкладки прокручиваются горизонтально.
- Обновлена регистрация: новые подсказки, повтор пароля, переключатель видимости пароля и индикатор надёжности.
- Добавлены горячие клавиши: Ctrl/⌘ + K — поиск чатов; Escape — выйти из чата на мобильном.

## Исправления
- Статусы «Прочитано»: после открытия переписки создаются строки в `message_reads`, сообщения перечитываются сразу после сохранения статуса, а другой клиент обновляет статусы через Realtime.
- Счётчики непрочитанных возле чатов обновляются по Realtime и через резервное обновление раз в 10 секунд, пока сайт открыт.
- Уникальные юзернеймы проверяются в PostgreSQL без учёта регистра; поиск принимает `@username`.
- Исправлена связь `conversation_members` → `profiles` через `conversation_members_user_profile_fkey`.
- Добавлены анимации появления сообщений и индикатора непрочитанных.
- SQL-файл включает таблицы, RPC, политики безопасности, хранилище файлов и Realtime в одном документе.

## Установка — в таком порядке

1. В Supabase открой **SQL Editor → New query**.
2. Открой файл `MilchikTG_FULL_DATABASE_ONE_FILE.sql` из этого архива, скопируй весь код и нажми **Run**.
3. В GitHub Pages-репозитории замени `index.html`, `style.css`, `script.js`, `sw.js` и добавь/обнови `manifest.webmanifest`, `icon.svg`.
4. В начале нового `script.js` вставь свои настоящие `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`. Не используй `service_role`/secret key.
5. Подожди публикации GitHub Pages и перезагрузи сайт через Ctrl+Shift+R. На телефоне закрой вкладку сайта и открой заново, если старый экран остался в кэше.

SQL-файл рассчитан на существующую базу и не содержит DROP TABLE. Он добавляет отдельный FK для профилей участников, чтобы запрос `profiles!conversation_members_user_profile_fkey(...)` работал.

## Проверка
1. В профиле установи юзернейм (3–24 символа: a-z, 0-9 и `_`). Если он занят, база не даст сохранить дубликат.
2. Открой два аккаунта в разных браузерах. Отправь сообщение с первого аккаунта.
3. Пока второй чат закрыт, на первом у чата должно быть число непрочитанных.
4. Открой переписку на втором аккаунте. На первом статус должен смениться на «Прочитано» (при включённом Realtime; резервный опрос обновит список чатов, но для мгновенного тика лучше, чтобы Realtime был включён).

Если SQL Editor покажет ошибку, не удаляй таблицы. Скопируй точный текст ошибки и проверь его до повторного запуска.
